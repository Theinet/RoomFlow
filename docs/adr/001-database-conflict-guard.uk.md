# ADR-001: захист від подвійного бронювання на рівні БД

[English](001-database-conflict-guard.md) · **Українська**

**Статус:** прийнято

## Контекст

Перевірка доступності лише у React або в Express не захищає від гонки: два
запити можуть одночасно побачити вільний слот і обидва спробувати його зайняти.

## Рішення

RoomFlow перевіряє інтервал на API-рівні для зрозумілої відповіді користувачу,
але остаточний інваріант забезпечують SQLite triggers на `INSERT` і `UPDATE`.
Конфлікт визначається формулою:

```text
new.start < existing.end AND new.end > existing.start
```

Суміжні інтервали дозволені. Trigger скасовує запис з `booking_conflict`, який
API перетворює на HTTP `409 Conflict`.

## Наслідки

- Конкурентні клієнти не можуть створити два перехресні бронювання навіть в
  обхід UI.
- Інтеграційний тест надсилає два одночасні запити та перевіряє `201 + 409` і
  рівно один запис у БД.
- Правило залежить від SQLite. Під час переходу на іншу БД його треба
  відтворити через її транзакційний механізм або constraint/trigger.
